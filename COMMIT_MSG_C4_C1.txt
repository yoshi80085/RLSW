C4 + C1: each style reads the chord context, and the payout is live

C4 - Style x chord context. B3's pardon skewed Style permanently: Flair pulled
with Theory while Shred and Groove were taxed for the same purchase, forever,
on account of a choice made at character select. Each style now has its own
read, and each is a real technique:

  Shred  - Chromatic Passing: a run travels THROUGH a pardoned note without
           breaking, and the note counts toward the length.
  Groove - Locked In: a pardoned note may anchor a pattern, and each
           occurrence counts double.
  Flair  - Outside: pardoned notes pay Db instead of Drive/Sustain.

styleCommitDb's `currentScale` is renamed `keyScale` to make the landmine hard
to step on: detectResolvedDiscords must keep receiving the UNEXTENDED key, or
pardoned notes stop reading as discords and Theory destroys the only style
built to reward it. It is the one detector that did not grow a context param,
and that refusal is now asserted three ways.

Flair's Outside sits alongside STYLE_DB_CAP rather than under it, against this
doc's own suggestion: under the cap a Flair spirit at tier 3 gets nothing at
all for Outside, so the flagship rule would go quiet exactly when they were
playing well. It follows B6's payout instead. Magnitude is provably unchanged
from B4, so it is a routing change, not a balance change.

C1 - Live style prediction. styleCommitDb was already pure and already took
exactly the arguments a preview needs, so the Commit Track now shows the payout
as the track is built, and shows the style's earnDesc when nothing qualifies.
Derived from melodyLine on render rather than bolted onto addNoteToTrack, so it
also covers the mixer, banked notes, undo, and revoicing the chord under an
unchanged track.

Two live balance bugs, both Groove's:

- The commit passed `rootNote: newRootRaw` - next turn's root, derived from the
  track's own last note. Groove's resolution bonus was comparing the last note
  against a respelling of itself: it fired on any track whose last note isn't
  in ENHARMONIC_RESPELL and never fired when a Groove spirit genuinely landed
  on A#/D#/E#/B#/Gb.

- Found by C1's fuzz: the mic's voice roll appends a random note at commit,
  which could overwrite a deliberate root landing and delete the bonus. Append
  is monotone everywhere else in the Style system; Groove's root test is the
  sole exception. New pure helper micBonusNote lands the vocal on the root
  instead whenever the roll would lower the payout - "don't make it worse"
  rather than "pick the best note", which would turn the roll into a free
  optimiser.

actingStyle is hoisted to the top of confirmNoteTrack; both new call sites sit
above its old declaration and a TDZ throw there deadlocks the turn.

b0check: 54 -> 60 assertion groups. The C1 fuzz generates musical shapes and
asserts its own warmth, having first been caught scoring on 155 of 4000 cases.
The two no-useless-assignment lint errors in styleCommitDb are fixed.
