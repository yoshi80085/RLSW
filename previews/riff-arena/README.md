# Riff Off: Soundform arena study

Run `npm run dev:riffarena`, or open `/RLSW/previews/riff-arena/` on the dev server.
The `.scratch/riff-arena-preview.html` entry opens the same implementation.

This is the tuning preview for the approved design now integrated into live
matches. This standalone page does not apply rewards, damage, or knockback to
game state; the live game does. No Spirit-back artwork was installed.

## What is playable

- The real arena GLB, Riven World scenery, and acrylic Spirit standees.
- Two instances of the existing `RiffHighway`, anchored to the Spirits on screen.
- Three to five notes per phrase, taken from the entered committed melody; an
  answer generated by the game's inversion/modulation/variation/resolution logic.
- Attacker calls, Rival answers; next exchange, Rival calls its own melody and
  attacker answers. Leaders continue alternating.
- One shared clock. The other lane falls during the current phrase; the next
  exchange is prepared ahead of time and discarded if the duel ends. Input
  windows never overlap. The opening 100 ms handoff is the gap *between timing
  windows* (about 474 ms between the last/first note centers at 138 BPM), and
  falls by 12% each exchange. Defaults start with four notes per volley.
- Successful notes power ring streams from the real arena's W-S/E-S speaker
  surfaces, resolved from their transformed meshes. The Sonic renderer supplies
  the actual two-band ring geometry and materials; the preview supplies a steady
  forward clock with fixed spacing. No held compression phase, beam stretching,
  or substitute amp props. Rings converge inside a central Soundform ball.
- Fourteen core rings rotate on independently tilted axes at unequal speeds and
  opposing directions. The ball begins small and grows with accumulated notes
  and elapsed duel time, capped spatially to preserve the arena view. Subtle
  glitter winds around the streams and core; its intensity can be turned off.
  Reduced motion freezes rotation and glitter, with growth only from new notes.
  Grade weights govern accumulated visual energy. The current exchange's performance decides
  the outcome; accumulated visual size does not secretly change scoring.
- Continuous duels begin with the game's 20-point quality gap. The threshold
  drops 2.5 points per exchange to a 4-point floor, independently of the timing
  windows that shrink with tempo. Thus closer performances are needed to keep
  trading as the duel escalates. These are adjustable preview defaults for Alex's
  requested escalation rule, not production balance changes. The two-round
  option keeps the fixed 20-point threshold and existing endpoint. Equal play
  never manufactures a winner. Existing verdict math supplies the winner and
  damage; later exchanges retain its round-two damage band.
- Watch a demo, play either seat against timed demo inputs, or share 1–6 between
  two players. Space pauses; changing tabs pauses. Reset applies timing/roster/
  melody changes. Board glow, ball size/growth/spin, stream speed, glitter,
  lane width and volume change live. The long-demo scenario uses fixed physical
  input jitter; it naturally breaks through as tempo and tolerance tighten.
- Local settings persistence and a selectable Copy dial-in block with defaults
  versus changes. This is URL-specific: copy settings before moving the preview.

The standees have a staged three-quarter inward turn to keep their sheets
readable. Their game facings and original front/back materials are unchanged.
Audio is a lightweight, panned audition voice, not the final rig
audio integration. The preview uses single-note gestures; production sustain,
bend and chord handling is included in the live integration. Riff Slayer and
E-Rush are retired in the current game.

## Validation

`npm run test:riffarena` checks deterministic generation, both leaders' melody
sources, note limits, empty material, look-ahead, exclusive judging windows,
wrong input and duplicate presses, expiry, resolution, continuing/two-round
rules, tempo-sensitive demo timing, and two real necks rendered together. It also
checks the real Sonic ring geometry, transformed amp sources, forward-only
fixed-spacing flow, independent core spin/growth, shrinking continuation gap,
cross-exchange input ownership, glitter, reduced motion, reset and disposal.
`node src/board/sonicRingCheck.mjs` checks the unchanged source Sonic renderer.

The only production component change is unique per-instance SVG paint-server
IDs in `RiffHighway`: two tracks must not share the same glow/gradient IDs.

## Live match integration — 2026-10-01

Approved and wired into the real Game through crossed Sonic beams. Production
uses `src/riff/arenaDuel.js` for short deterministic schedules and
`src/ui/RiffArenaBattle.jsx` for both projected tracks. The visual factory lives
in `src/board/riffWaveforms.js`; this preview re-exports it.

- Each seat's `lastCommittedMelody` survives turn reset. Three-note melodies stay
  three beats; longer melodies supply four. Chord partners share the root beat.
- Current and upcoming charts are engine-owned. Leaders alternate indefinitely
  while performance remains close. Tempo rises 138 → 240 BPM; tolerance falls
  20 → 4 quality points. Scores are normalized for unequal chord-gem counts.
- Bots use seeded timing offsets against the same windows as humans. That is an
  explicit gameplay model, not a fitted model of student performance.
- Results identify the round and clock revision. Duplicate/stale submissions
  cannot replace completed performances. Late exchange decisions restore a
  visible lead-in; returning players can request a pending-performance restart.
- Both native amp voices play through the live audio path. Existing damage,
  knockback, Fame, consolation and Headliner handling runs after breakthrough.
- The 3D adapter uses actual cabinet origins, smooth ball movement/growth and
  stronger standee shaking as the core grows. Board hexes/facings are untouched.
- Old versionless action logs retain their legacy duel behavior.

`test:riffarenalive` runs 16 engine/visual checks and 10 mounted input scenarios.
`test:riffarenajourney` exercises normal Game targeting plus recorded-result
aftermath. Browser verification completed a three-exchange bot duel in the real
Game. Two-device online timing remains a playtest item; clocks currently use
the shared wall-clock epoch. The full suite stops at the pre-existing combat
assertion in `selftest.mjs:457` (4 versus 11), before reaching these suites.

No new wager, shield damage or payout formula was added. The 64-exchange bound
exists only in bot search: it returns an unresolved forecast, never a winner.
